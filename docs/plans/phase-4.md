# Phase 4: evaluation, server and GPU metrics, energy and CO2, media

Reference: `genai_otel_instrument` v1.30.0. Contract: `contract/eval_rules.json`,
`contract/eval_vectors.json`, `contract/metrics.json`, `contract/PORTING_NOTES.md`
sections 5 and 6. Design: section 7 of the multi-language SDK design.

## Rules that decide the shape of this phase

- **Unmeasured is absent, never zero.** A host with no GPU has no GPU metric. A run with
  no carbon intensity has no CO2 metric. A detector with no backend writes no attribute.
- **Detector rules are data, not code.** Patterns, keyword lists and scores come from
  `contract/eval_rules.json`, vendored by `scripts/sync-from-python.mjs`; the generator
  turns them into a module so the browser and React Native entries can use them without
  reading a file. Nothing is typed in by hand.
- **`eval_vectors.json` is what verifies a detector**, not the prose in the rules file.
  Every vector is a test.
- **No Python, no network.** Presidio, Detoxify, Perspective and codecarbon have no
  place here. What they would add is a plug-in the application supplies.

## Toxicity

The reference has no rule-based toxicity mode: without Detoxify or the Perspective API
its detector returns "not toxic" for every input, and its span processor then writes
`evaluation.toxicity.<prompt|response>.detected = false`.

That `false` is not a measurement. Here, **with no backend configured, no toxicity
attribute and no toxicity metric is written.** With a backend (a function the application
supplies: an ONNX model, or a call to an on-prem endpoint) the attributes are the
reference's. This is a deliberate difference, decided by the lead, and is listed in the
parity matrix. The 24 toxicity vectors pin the reference's detector result for the
no-backend case; they are checked against the detector's own return value, which stays
the reference's, and the span-level difference is tested separately.

`GENAI_TOXICITY_USE_PERSPECTIVE_API` is honoured only with `GENAI_ALLOW_EXTERNAL_EGRESS`
set and `GENAI_AIR_GAPPED` not set, as in the reference. No Perspective client ships.

## Judge plug-in

One interface for anything a rule cannot decide: `(kind, text, context) -> result`.
Used for toxicity, and optionally to replace the PII regex fallback or the hallucination
heuristics. Two implementations are documented, neither is a dependency: a local ONNX
model through `onnxruntime-node`, and an HTTP call to an on-prem OpenAI-compatible
endpoint. The HTTP one ships; the ONNX one is an example. A judge that throws or times
out leaves the attribute absent and logs once.

## GPU on Node

There is no NVML binding to depend on. `nvidia-smi --query-gpu=... --format=csv` is run
on the collection interval, off the request path, with a timeout.

| Situation | Behaviour |
|---|---|
| No `nvidia-smi` on the host | no GPU instruments are created; one log line at info level |
| `nvidia-smi` present but failing (driver mismatch, no devices) | the same; after repeated failures collection stops instead of retrying forever |
| A field reported as `[N/A]` or `[Not Supported]` | that gauge reports nothing for that GPU; the others do |

Browser and React Native: no GPU, energy or CO2 metrics at all (the design says so).

## Energy and CO2

The reference delegates to codecarbon, which carries its own regional data and measures
CPU and RAM as well. Here:

- **Energy** is integrated from measured GPU power between samples. CPU power is added
  only where the host exposes it (Linux RAPL, readable). No estimate from TDP.
- **CO2** is energy times carbon intensity. The intensity comes from
  `GENAI_CARBON_INTENSITY`. The design also names a vendored country and region table;
  **the staged contract (v1.30.0) does not contain one**, and contract data is never
  typed in by hand. Until the lead adds it to the staging directory, a run without
  `GENAI_CARBON_INTENSITY` records energy and no CO2, and says so once in the log.
  Reported to the lead.

## Not in this phase

- Presidio-grade PII (names, locations): only the reference's regex fallback is ported;
  12 of its 22 entity types have no pattern there either.
- The Perspective API client.
- Anything in a real browser or on a device; any run against a GPU host. Those are the
  lead's runs.
